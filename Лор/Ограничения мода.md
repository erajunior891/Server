## 🖥️ Аппаратные Характеристики Сервера
- **Процессор**: Intel Core i7-11700K (4 vCPU выделено)
- **Оперативная память**: DDR4 3200MHz — 8 ГБ RAM
- **Дисковая подсистема**: SSD M.2 NVMe — 16+ ГБ NVMe ROM
- **Ядро сервера**: Endstone Core 0.11.12+ (Minecraft Dedicated Server Bedrock)
- **Целевая версия игры**: Bedrock Edition 1.21.50 – 1.26.51+

## 🚧 Анализ Ограничений Bedrock Edition и Решения

В отличие от Java Edition, закрытый клиент Bedrock накладывает ряд ограничений. Ниже описаны возникшие вызовы и инженерные решения для их преодоления.

### 1. Голосовой чат (Voice Chat)
- **Проблема**: Закрытый клиент Bedrock не позволяет инжектировать аудио-потоки напрямую в GUI игры без кастомных сборок клиента (что исключает игру с консолей и мобильных платформ).
- **Решение**:
  - Использование внешнего Discord-бота синхронизации позиционного звука или стороннего клиента (например, Bedrock Simple Voice Chat / Mumble Link).
  - Внутриигровые визуальные индикаторы речи и состояния здоровья через Endstone Action Bar и Titles.

### 2. Кастомные GUI и Меню
- **Проблема**: В Bedrock нельзя создавать произвольные окна инвентаря так же свободно, как в Java Spigot (chest commands).
- **Решение**:
  - Использование нативного интерфейса Bedrock Server Form (`ActionFormData`, `ModalFormData`, `MessageFormData`) через Endstone Python/C++ API.
  - Команда `/sculk` вызывает нативную всплывающую панель с кнопками, слайдерами и детальной статистикой.

### 3. Распространение блоков скалка при смертях
- **Проблема**: Стандартный Bedrock Behavior Pack не всегда успевает зафиксировать координаты гибели игрока в момент смерти с нужной точностью.
- **Решение**:
  - Серверный плагин перехватывает событие `onPlayerDeath` на уровне ядра Endstone. При 4 стадии чумы плагин напрямую выполняет генерацию блока `sculk_catalyst` по точным координатам игрока.

### 4. Производительность при расчёте дистанции
- **Проблема**: Постоянный опрос координат всех игроков в Python на каждом тике может вызывать micro-stutter при онлайне 20+ человек.
- **Решение**:
  - Выполнение пространственных расчётов через C++ модуль `cpp_sculk_plugin` или распределение тиков проверки через планировщик Endstone Scheduler раз в 1–2 секунды (каждые 20–40 тиков) вместо каждого тика.
